#### ✅ Amendment #1: Section 4.3 - P2P Version Negotiation (20 min)

**What was added:**
- Complete P2P handshake protocol for WebRTC DataChannel connections
- `PeerHandshake` and `PeerHandshakeAck` message types (fields 29-30)
- Ed25519 signature verification for peer identity authentication
- Version negotiation algorithm: `min(initiator_version, responder_version)`
- Incompatible version handling with graceful DataChannel closure
- Security considerations: replay attack prevention via timestamp validation
- Integration with WebSocket signaling phase (references protocol-phase2-design.md)
- Comprehensive test requirements (4 new test cases)
- Backward compatibility analysis (no impact on WebSocket-only clients)

**Key design decisions:**
- Initiator = peer who sent WebRTCOffer, sends first PeerHandshake over DataChannel
- Signature binds protocol_version to Ed25519 peer_id (prevents MITM)
- Fallback to WebSocket on handshake failure (graceful degradation)
- Field numbers 29-30 follow Phase 2 WebSocket messages (18-28)

**Coordination note:** Aligned with rust-engineer-protocol's protocol-phase2-design.md (660 lines, fields 18-28 for WebSocket messages)

#### ✅ Amendment #2: Protocol Version Number Standardization (5 min)

**What was fixed:**
- **Line 204 contradiction resolved**
  - OLD: "1 = v1.0, 2 = v1.1"
  - NEW: "0 = v1.0, 1 = v1.1, 2 = v1.2" (zero-indexed)
  
**Rationale:**
- Protobuf3 defaults missing `uint32` to 0
- v1.0 clients (who don't send `protocol_version` field) naturally map to 0
- Consistent with protobuf defaults, clearer semantics

**Impact:** All version negotiation examples now use zero-indexed mapping throughout ADR-004
