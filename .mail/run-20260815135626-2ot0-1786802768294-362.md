### Integration Point 2: Working Directory Change 🔶

**Challenge:** ConPTY provides raw PTY output only. We don't parse shell commands.

**Problem:**
- PTY output is opaque byte stream (ANSI escape codes + text)
- No built-in `cd` detection in ConPTY backend
- Shell-specific command parsing is fragile (pwsh vs cmd vs bash)

**Options:**

**Option A: Parse PTY Output (Fragile)**
- Detect prompt changes (e.g., "C:\Users\..." → "C:\Projects\...")
- Requires shell-specific heuristics
- Error-prone (ANSI codes, custom prompts, etc.)
- **Not recommended for Phase 1**

**Option B: Poll Working Directory (Safe but Inefficient)**
```rust
// In pty_output_loop, every 5 seconds:
if last_cwd_check.elapsed() > Duration::from_secs(5) {
    // Get shell PID's current working directory via Windows API
    let current_cwd = get_process_cwd(session.shell_pid)?;
    if current_cwd != session.working_dir {
        session.working_dir = current_cwd.clone();
        // Trigger monomind detection
        tokio::spawn(monomind_bridge::detect_project(current_cwd));
    }
}
```
- Pros: Works reliably, no parsing needed
- Cons: 5s poll overhead, requires Windows API call per session

**Option C: Defer to Phase 2**
- Phase 1: Detect only on session creation
- Phase 2: Add shell integration hooks (when we have proper command interception)

**Recommendation:** **Option C (Defer to Phase 2)** for MVP simplicity.

**Rationale:**
- Session creation hook covers 80% of use cases (user starts terminal in project dir)
- Working directory change is rare in terminal workflows
- Phase 2 can add proper shell integration when we implement command history/interception

**Alternative:** If critical for Phase 1, use Option B (polling).
