## Product Owner Decision: ✅ AUTHORIZE MVP RENDERING SCOPE

### Phase 1 Gate Minimum (ADR-011)

**SRS §7.1 Acceptance Criterion #1**: "60 FPS master rendering on Windows 10 1809+"

This criterion does NOT specify rendering complexity, only that 60 FPS is achieved. Therefore, MVP scope for Phase 1 gate is:

#### ✅ **MVP Rendering Scope (Phase 1 Gate Pass)**
1. **Single terminal window** with basic text output (e.g., `echo "Hello World"` or simple shell prompt)
2. **60 FPS measured frame rate** (proves wgpu + DirectX 12 pipeline works on Windows 10 1809+)
3. **Production wgpu pipeline** (not a mock/demo - actual DirectX 12 backend)
4. **Integrated with master daemon** (rendering loop connected to PTY I/O, even if content is simple)
5. **Basic text rendering** (ASCII characters, single line or simple grid, no complex glyph shaping required)

#### ❌ **Deferred to Phase 1.5 (Post-Gate, Pre-Phase 2)**
1. Full scrollback rendering (10k lines)
2. Complex glyph shaping (HarfBuzz, ligatures, emoji)
3. Full VT100/ANSI escape sequence support
4. Multi-window/split-pane rendering
5. Advanced text styling (bold, italic, underline beyond basic)

**Rationale**: Phase 1 goal is to "prove the architecture end to end before expanding" (SRS §7.1). MVP rendering proves:
- ✅ wgpu works on Windows/DirectX 12
- ✅ 60 FPS target is achievable
- ✅ Rendering integrates with PTY I/O
- ✅ Architecture is sound

Full feature set is implementation work, not architecture validation.
