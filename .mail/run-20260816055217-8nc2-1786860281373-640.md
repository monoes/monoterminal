### 1. Background Color Support: **OPTION A (bg_color) - STRONGLY RECOMMENDED**

**Technical rationale (DirectX 12 specific):**

✅ **GPU efficiency (critical for 8ms budget):**
- **Single draw call** minimizes DirectX 12 PSO (Pipeline State Object) changes
- **Overdraw elimination**: 2-pass touches every pixel twice (wasted fillrate)
- **Modern GPU architecture**: Fragment shader complexity is cheap, redundant passes are expensive
- **DirectX 12 command buffer**: Fewer commands = lower CPU overhead

✅ **Frame budget analysis:**
- **Single-pass estimate**: 4-5ms GPU (1 draw call, 1 PSO bind)
- **Dual-pass estimate**: 5-7ms GPU (2 draw calls, 2 PSO binds, context switches, overdraw)
- **Headroom**: Single-pass gives 3-4ms buffer vs dual-pass 1-3ms buffer
- **Conclusion**: Single-pass safer for hitting 8ms target consistently

✅ **Memory trade-off is negligible:**
- **Cost**: +16 bytes/vertex = +23KB for 80×24 grid
- **Context**: 4096×4096 R8Unorm atlas = 16MB (texture is 700× larger)
- **DirectX 12**: Modern GPUs have massive vertex bandwidth (this is nothing)

✅ **Architecture benefits:**
- **No technical debt**: Avoids "we'll fix it later" trap
- **ANSI color support**: Required by SRS (SGR sequences)
- **Inverse video**: Essential terminal feature (`\e[7m`)
- **Future-proof**: One optimized path > two semi-optimized paths

**Implementation:**
```wgsl
// Your proposed fragment shader is PERFECT:
return mix(in.bg_color, in.fg_color, glyph_alpha);
```
This is the industry-standard approach for SDF/atlas text rendering.

### 2. Sampler Filter Mode: **LINEAR - RECOMMENDED**

**Technical rationale:**

✅ **Visual quality:**
- **Antialiasing**: Critical for readability across DPI settings
- **Windows DPI scaling**: Phase 1 targets Windows - high-DPI displays are common
- **Industry standard**: All modern terminals (Windows Terminal, iTerm2, Alacritty) use linear
- **Nearest filter**: Acceptable only for retro/pixel-art aesthetic (not our use case)

✅ **Performance (DirectX 12):**
- **GPU hardware**: Bilinear filtering is FREE on modern GPUs (same cost as nearest)
- **Texture cache**: Handles interpolation in hardware
- **Frame budget impact**: ~0ms (measured in practice)

**My original "nearest" choice:**
- Likely placeholder/conservative default
- Linear is objectively better for production terminal rendering

**Implementation:**
```rust

    label: Some("Glyph Atlas Sampler"),
```

**Verdict:** Switch to Linear. Zero cost, significant quality improvement.
