### 2. MSI Installer - Implementation Approach

**Toolchain Decision: WiX Toolset v4 + cargo-wix**

#### Why WiX v4?
- Industry standard for Windows installers
- Native Rust integration via `cargo-wix`
- Supports service installation/removal
- Code signing integration
- Custom actions for service registration

#### Implementation Plan

**Phase A: WiX Project Setup (3 days)**
```toml
# Cargo.toml additions
[package.metadata.wix]
name = "MONOTERMINAL"
manufacturer = "MONOTERMINAL Team"
product-icon = "assets/icon.ico"
dialog-image = "assets/dialog.bmp"
banner-image = "assets/banner.bmp"
upgrade-guid = "<STABLE-GUID>"  # Generate once, never change
```

**Phase B: Service Integration (2 days)**
- Custom action: Install service via `sc create` during MSI installation
- Custom action: Start service post-install
- Custom action: Stop + delete service during uninstall
- Rollback actions on installation failure

**Phase C: CI/CD Integration (2 days)**
```yaml
# .github/workflows/release.yml addition
- name: Build MSI (Windows)
  run: |
    cargo install cargo-wix
    cargo wix --nocapture --output target/wix/monoterminal.msi
```

**Total: 1 week** (can start immediately, parallel to service implementation)

**Deliverable:** MSI installer with:
- Start Menu shortcut
- Add/Remove Programs entry
- Service installation/uninstallation
- Config file initialization
- Automatic updates via reinstall-over-existing

### 3. Code Signing - Certificates & Process

**Status: 🔴 BLOCKING - No certificates acquired yet**

#### Certificate Procurement (Week 1)

**Recommended Provider:** DigiCert or Sectigo
- **Certificate Type:** EV (Extended Validation) Code Signing
- **Cost:** $200-400/year (per SRS §9.3 budget allocation)
- **Timeline:** 3-5 business days (after business verification)

**Requirements for EV Certificate:**
- Business verification (company registration docs)
- Physical USB token (ships with certificate, required for signing)
- Windows host for signing (EV certs require hardware token, can't be extracted)

**DECISION NEEDED:** 
- Do we have a registered business entity for certificate issuance?
- Who will be the certificate owner/custodian?
- Billing approval for $200-400/year recurring cost?

#### Signing Process (Week 2)

**Local Signing (Development):**
```powershell
# Using signtool.exe (Windows SDK)
signtool sign /f cert.pfx /p <password> /tr http://timestamp.digicert.com /td sha256 /fd sha256 monoterminal.msi
```

**CI/CD Signing (Production):**
- **Option A:** Azure SignTool + Azure Key Vault (GitHub Actions)
  - Certificate stored in Azure Key Vault
  - GitHub Actions authenticates via OIDC
  - No secrets in repo
  - Cost: ~$5/month for Key Vault

- **Option B:** Self-hosted runner with USB token
  - GitHub Actions runs on self-hosted Windows machine
  - USB token physically attached
  - More secure, but requires dedicated hardware

**Recommendation:** Option A (Azure SignTool) for Phase 1 simplicity

#### Signing Integration
```yaml
# .github/workflows/release.yml
- name: Sign MSI
  uses: azure/azure-code-signing-action@v3
  with:
    azure-vault-name: ${{ secrets.AZURE_VAULT_NAME }}
    certificate-name: ${{ secrets.CERT_NAME }}
    files: target/wix/monoterminal.msi
```

**My deliverable:** Signing pipeline setup (after certificate procurement)

### 6. Web Deployment Impact (localhost:8080)

**Analysis: ✅ SIMPLIFIES DevOps**

#### What This Means
- Web client is served by the master daemon itself (static file server on localhost:8080)
- No external web hosting (no Vercel/Netlify/CloudFlare costs)
- No public TLS certificate needed (localhost = HTTP is fine, or self-signed cert)
- No CDN, no DNS configuration

#### DevOps Implications
1. **MSI must include web client assets:**
   - Bundle `web/dist/` into MSI at install time
   - Install location: `C:\Program Files\Monoterminal\web\`
   - Daemon serves from this path

2. **Service must serve static files:**
   - Ensure master daemon includes HTTP static file handler (rust-backend-lead's concern)
   - Default route: `http://localhost:8080` → PWA entrypoint

3. **No external infrastructure needed:**
   - No web hosting budget line item
   - No SSL certificate renewal automation
   - No CDN cache invalidation

**Net Impact: Reduces scope** (one fewer system to manage)
