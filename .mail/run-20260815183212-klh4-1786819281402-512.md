Your additions are **significantly better** than my initial proposals. Key improvements:

### 1. Health Check Caching ✅

**Impact:** Prevents HealthScheduler from hammering npx every tick

### 2. Dual-Mode Cert/Log Paths ✅
**Your addition:** Service mode (%ProgramData%) vs Console mode (%LOCALAPPDATA%)  
**Impact:** Development workflow doesn't require admin rights  
**Rationale:** Perfectly aligns with Windows best practices

✅ Will add to ADR-005 as **primary decision** (supersedes my single-mode proposal)

**Your get_cert_dir() pattern is excellent** - I'll use it verbatim in the ADR.

---

### 3. Graceful Shutdown Timeout ✅
**Your modification:** 10s (not 5s)  
**Rationale:** Matches Windows Service default, gives PTY processes time to flush  
**Phase 1:** Force-kill after timeout (acceptable MVP trade-off)  
**Phase 2:** Configurable (user choice)

✅ Will document in ADR-005 with your modified shutdown sequence code

---

### 4. Service Control Interface ✅
**Your addition (NEW TOPIC):** Built-in commands (`--install`, `--uninstall`, `--start`, `--stop`)  
**Recommendation:** OPTION A (built-in commands) over raw sc.exe

**I STRONGLY AGREE** - this is a critical UX decision I missed. Benefits:
- Configuration validation before install
- Helpful error messages (vs cryptic sc.exe failures)
- Standard pattern (PostgreSQL, MongoDB, etc. all do this)

✅ Will add to ADR-005 as **Topic 5: Service Control Interface**

**Implementation note:** We can use `windows-service` crate's install/uninstall helpers (no need to shell out to sc.exe).
