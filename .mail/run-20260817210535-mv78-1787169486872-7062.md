### Architecture Highlights

**systemd (Linux):**
- Type=notify service with sd-notify protocol
- Direct socket notification (no libsystemd dependency)
- Dedicated service user: `monoterminal`
- System directories created via StateDirectory/LogsDirectory
- Security sandboxing (ProtectSystem, ProtectHome, NoNewPrivileges)
- Auto-restart on failure (Restart=on-failure, RestartSec=5s)
- Boot auto-start (WantedBy=multi-user.target)

**launchd (macOS):**
- Launch daemon (system-level, not launch agent)
- Dedicated service user: `_monoterminal` (underscore prefix)
- Working directory: /Library/Application Support/MONOTERMINAL
- Logs: /Library/Logs/MONOTERMINAL/
- Auto-restart on crash (KeepAlive=true)
- Boot auto-start (RunAtLoad=true)
- Resource limits (soft + hard)

**Unified CLI:**
- `monoterminal-master install-service` (requires sudo)
- `monoterminal-master uninstall-service` (requires sudo)
- `monoterminal-master service-status` (check status)
- Platform detection (Linux vs macOS)
- Privilege checking (requires root)
- Idempotent operations (safe to run multiple times)

### Security Design

**Principle of least privilege:**
- Dedicated service users (not root after startup)
- systemd: User=monoterminal, Group=monoterminal
- launchd: UserName=_monoterminal, GroupName=_monoterminal

**systemd sandboxing:**
- NoNewPrivileges=true (prevent escalation)
- PrivateTmp=true (private /tmp)
- ProtectSystem=strict (read-only /usr, /boot, /efi)
- ProtectHome=true (no access to /home)
- ReadWritePaths=/var/lib/monoterminal /var/log/monoterminal

**Resource limits:**
- File descriptors: 65536 (for 1000-session target, SRS §5.1.1)
- Processes: 512 (PTY spawning limit)

**File permissions:**
- Service files: 0644 (read-only for non-root)
- Directories: 0755 (rwxr-xr-x)
- Database: 0644 (rw-r--r--)
