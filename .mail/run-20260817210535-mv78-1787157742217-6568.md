## Executive Summary

Phase 3 extends MONOTERMINAL from Windows-only to full cross-platform support (Linux + macOS). **Zero client work required** — web PWA already works cross-platform.

**Effort:** 3 months, 1.5 engineers (aligns with SRS §7.3)

**Key Findings:**
- ✅ PTY abstraction already exists (`PtyBackend` trait)
- ✅ wgpu rendering already cross-platform (Vulkan/Metal/DX12)
- ⚠️ Need Unix PTY implementation (portable-pty crate recommended)
- ⚠️ Need systemd (Linux) + launchd (macOS) service management
- ⚠️ Need cross-platform CI matrix (Ubuntu + macOS + Windows)

---

## Architecture Gaps Identified (5 categories)

### 1. PTY Layer (CRITICAL)
**Status:** Windows ConPTY implemented, Unix PTY missing

**Recommendation:** Use `portable-pty` crate with adapter to existing `PtyBackend` trait
- ✅ Mature crate (~40k downloads/month)
- ✅ Faster time-to-market (2 weeks vs 4-5 weeks from scratch)
- ✅ Existing `PtyBackend` trait already designed for cross-platform

**Effort:** 2 weeks (Week 1-2 of Phase 3)

### 2. Service Management (HIGH-PRIORITY)
**Status:** Windows Service implemented, systemd/launchd missing

**Platforms:**
- Linux: systemd Type=notify (readiness signaling)
- macOS: launchd KeepAlive (restart on crash)

**Socket Activation:** Deferred to Phase 3.5 (not required for feature parity per SRS §7.1)

**Effort:** 1 week (Week 3 of Phase 3)

### 3. Rendering (LOW-PRIORITY)
**Status:** wgpu already supports Vulkan (Linux) + Metal (macOS)

**No code changes required** — just verification testing on target platforms

**Effort:** 3 days (Week 4, parallel)

### 4. File Paths & Platform APIs (MEDIUM-PRIORITY)
**Status:** Windows paths implemented (`%ProgramData%`, `%LOCALAPPDATA%`)

**Need Unix paths:**
- Linux: `/var/lib/monoterminal`, `~/.local/share/monoterminal`
- macOS: `/Library/Application Support/MONOTERMINAL`, `~/Library/Application Support/MONOTERMINAL`

**Effort:** 2 days (Week 1 of Phase 3)

### 5. Build Matrix & CI (HIGH-PRIORITY)
**Status:** Windows CI implemented, Linux + macOS missing

**Required:** GitHub Actions matrix (Ubuntu 22.04, macOS 13, Windows)

**Effort:** 1 week (Week 5 of Phase 3)

## Proposed ADRs

### ADR-015: Cross-Platform PTY Abstraction
**Decision:** Use `portable-pty` crate with thin adapter to `PtyBackend` trait

**Alternatives:**
- Option A (CHOSEN): portable-pty + adapter (2 weeks, lower risk)
- Option B: From-scratch (~1,500 LOC unsafe FFI, 4-5 weeks, higher risk)

**Implementation:** `crates/master/src/pty/unix.rs` (~500 LOC adapter)

### ADR-016: Cross-Platform Service Management
**Decision:** Platform-specific service management with unified CLI

**Platforms:**
- Linux: systemd Type=notify
- macOS: launchd KeepAlive
- Windows: Windows Service (already implemented)

**Unified CLI:** `monoterminal-master install-service` (works on all platforms)

### ADR-017: Cross-Platform Distribution Strategy
**Decision:** Multi-channel distribution per platform

**Channels:**
- Linux: apt (.deb), rpm, standalone tarball
- macOS: Homebrew, standalone DMG
- Windows: Standalone binary (already implemented)
