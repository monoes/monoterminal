### 1. ADR-011: P2P Networking Architecture ✅
**Location:** `docs/decisions/011-p2p-networking-architecture.md`

**Key Decisions:**
- Hub-and-spoke topology (client→master, not full mesh)
- Dual-transport: WebSocket + WebRTC DataChannel (both active, instant fallback)
- NAT traversal: STUN (0-10s) → TURN (10-15s) → WebSocket fallback
- Discovery: Hybrid mDNS (LAN) + Directory Service (internet)
- Expected NAT success: 98-99% total (65-80% STUN direct, rest TURN/fallback)

**Implementation roadmap:** Weeks 1-6 (WebRTC foundation, NAT traversal, discovery)

---

### 2. ADR-012: Persistence Layer Design ✅
**Location:** `docs/decisions/012-persistence-layer-design.md`

**Key Decisions:**
- SQLite with WAL mode (readers don't block writers)
- Two-tier scrollback: Hot (10k lines RAM) + Cold (disk, zstd compressed)
- Schema migrations with version tracking (forward-only, idempotent)
- Write batching: 100 lines/batch, 100ms flush interval
- Compression: 60-80% reduction (4KB → 800B-1200B)

**Performance targets:**
- Fetch 1000 lines: <100ms p95 (including decompression)
- Write 100 lines: <50ms p95 (batched)
- DB size: <1GB for 100 sessions × 100k lines

**Implementation roadmap:** Weeks 2-3 (parallel to WebRTC foundation)

---

### 3. ADR-013: Multi-Session Architecture ✅
**Location:** `docs/decisions/013-multi-session-architecture.md`

**Key Decisions:**
- Session lifecycle extended: CREATE → RUNNING → DETACHED → TERMINATED
- DETACHED state: 24-hour TTL (sessions persist when clients leave)
- Client multiplexing: One WebSocket → many sessions (routing by session_id)
- Session discovery: ListSessionsRequest API with filtering
- Resource quotas: Max 100 sessions (SRS §7.2), max 10/user

**Implementation roadmap:** Weeks 4-5 (depends on persistence layer)

---

### 4. ADR-014: Collaboration Primitives ✅
**Location:** `docs/decisions/014-collaboration-primitives.md`

**Key Decisions:**
- Broadcast model (all clients see same output, not independent cursors)
- Presence tracking: ClientPresence, 30s heartbeat, 2min eviction
- RBAC: owner/editor/viewer roles (per SRS §2.1.5)
- Input conflict resolution: FIFO queue (no locking in Phase 2)
- JWT integration: Extract user_id from "sub" claim, check ACL

**Implementation roadmap:** Weeks 6-7 (depends on multi-session architecture)
