**Implementation Highlights:**

1. **Health Check Execution:**
   - Spawns blocking task for `npx monomind@latest doctor --json`
   - Graceful handling: not installed, command failed, JSON parse error
   - Returns `HealthStatus` with detailed issues (never panics)

2. **Doctor Output Parsing:**
   ```json
   {
     "version": "1.2.3",
     "controlServer": { "reachable": true },
     "broker": { "registered": true },
     "issues": [
       {
         "severity": "error",
         "message": "Control server unreachable",
         "resolution": "Check if server is running"
       }
     ]
   }
   ```
   - Missing fields default to false (defensive)
   - Issues array optional (empty if none)

3. **Upgrade Flow:**
   - Captures old version before upgrade
   - Runs `npx monomind@latest upgrade`
   - Captures new version after upgrade
   - Returns full output for UI display

4. **Health Scheduler:**
   - Default 24-hour interval (configurable)
   - Async callback receives `HealthStatus` on each check
   - Runs indefinitely until cancelled
   - Errors surface as `HealthStatus` with Error severity

**Design Principles Applied:**

✅ **Fail Loud, Not Silent:**
- Every failure → explicit `HealthIssue` with severity
- No silent drops (monoes/monomind#135 prevention)
- No dead connections (monoes/monomind#136 prevention)

✅ **Observable:**
- Tracing at debug/info/warn/error levels
- Structured logs for all operations
- Easy to diagnose failures

✅ **Defensive Parsing:**
- Missing JSON fields → safe defaults
- Invalid severity → filtered out
- Malformed JSON → clear error message
