### API Contract Needed

Need to define WebSocket Protocol Buffers messages for:

#### 1. Health Check (equivalent to `npx monomind doctor`)

**Request:**
```protobuf
message MonomindHealthCheckRequest {
  string project_dir = 1;  // Working directory to check (from session metadata)
}
```

**Response:**
```protobuf
message MonomindHealthCheckResponse {
  string version = 1;              // e.g., "1.2.3"
  bool installed = 2;              // Is monomind CLI installed?
  bool control_server_reachable = 3;
  bool broker_registered = 4;
  int64 last_check_timestamp = 5;  // Unix timestamp
  repeated HealthIssue issues = 6;
}

message HealthIssue {
  IssueSeverity severity = 1;
  string message = 2;
  string resolution = 3;  // Optional fix suggestion
}

enum IssueSeverity {
  INFO = 0;
  WARNING = 1;
  ERROR = 2;
  CRITICAL = 3;
}
```

**Notes:**

- Health check should be non-blocking (async)
- Per SRS §2.4.2, runs on schedule + on-demand

### Integration Architecture Questions

#### Option A: Extend Existing Protocol (monoterminal.v1.Envelope)

Add to `protocol/proto/protocol.proto`:
```protobuf
message Envelope {
  uint64 sequence_number = 1;
  oneof message {
    // ... existing messages ...
    MonomindHealthCheckRequest monomind_health_check_request = 20;
    MonomindHealthCheckResponse monomind_health_check_response = 21;
    MonomindUpgradeRequest monomind_upgrade_request = 22;
    MonomindUpgradeResponse monomind_upgrade_response = 23;
    MonomindStatusUpdate monomind_status_update = 24;
  }
}
```

**Pros:** Single protocol, single WebSocket connection
**Cons:** Couples terminal protocol with monomind features

#### Option B: Separate Protocol (monomind.v1.Envelope)

Create new proto file, reuse WebSocket connection with different message namespace.

**Pros:** Clean separation, easier to version independently
**Cons:** Slightly more complex routing in WebSocket handler

#### Recommendation: Option A (Extend Existing Protocol)

Rationale:
- Single WebSocket connection (per SRS §2.4.2 "same JWT auth")
- Simpler client implementation (already has Envelope handling)
- Monomind integration is first-class feature, not addon
- Field numbers 20+ are available in Envelope
