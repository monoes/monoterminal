### 📋 Protocol Design Notes (from ADR-004 §4.4)

**Why structured fields (not JSON):**
- Type safety: Frontend TypeScript interfaces match protobuf 1:1
- Performance: No JSON parsing, smaller wire size
- Schema evolution: Can add fields incrementally
- Consistency: Matches `MonitoringData` pattern

**DashboardResponse structure:**
```protobuf
message DashboardResponse {
  string org_name = 1;
  string org_status = 2;  // "running" | "stopped" | "error"
  repeated AgentInfo agents = 3;
  repeated TaskInfo tasks = 4;
  KnowledgeGraphStats kg_stats = 5;
  int64 timestamp = 6;
}
```

**No `json_data` field** (removed in pre-release revision, see PROTOCOL_CHANGELOG.md v1.0).

### 🚨 Common Integration Pitfalls (Avoid These)

**1. Silent Failures:**
```rust
// ❌ BAD: Swallow errors
let health = run_doctor_check(path).await.unwrap_or_default();

// ✅ GOOD: Fail loud (per SRS §2.4)
let health = run_doctor_check(path).await
    .map_err(|e| ErrorResponse {
        code: ErrorCode::ServerError,
        message: format!("Health check failed: {}", e),
    })?;
```

**2. Blocking Async:**
```rust
// ❌ BAD: Blocks WebSocket thread
let result = std::thread::spawn(|| run_doctor_check(path)).join()?;

// ✅ GOOD: Async all the way
let result = run_doctor_check(path).await?;
```

**3. Global Scope (Instead of Session):**
```rust
// ❌ BAD: Global health check (wrong per SRS §2.4.1)
let health = run_doctor_check(Path::new("/")).await?;

// ✅ GOOD: Per-session scope
let health = run_doctor_check(&session.working_dir).await?;
```

**4. Missing JWT Auth:**
```rust
// ❌ BAD: No auth check
handle_dashboard_request(req).await?;

// ✅ GOOD: Verify JWT before processing
verify_session_jwt(&req.auth_token)?;
handle_dashboard_request(req, &session).await?;
```
