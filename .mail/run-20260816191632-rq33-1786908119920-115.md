## Question 1: Systemic Architecture Issues vs Implementation Bugs?

**Answer: HYBRID - Implementation bugs revealing a systemic gap in lifecycle ownership**

### Root Cause Analysis

#### Issue #1: Heap Corruption (STATUS_HEAP_CORRUPTION)

**Location:** `crates/master/src/pty/conpty.rs`

**Mechanism:**
1. **Double-close race** on Windows HANDLE resources
2. Path: `ConPtyBackend::terminate()` (lines 318-333) calls `ClosePseudoConsole(self.hpc)` + `CloseHandle(process_handle)`
3. THEN: `Drop` impl (lines 336-346) calls THE SAME cleanup functions
4. Result: Windows heap corruption (0xc0000374) when both paths execute

**Code Evidence:**
```rust
// terminate() method (line 318-333)
async fn terminate(self) -> PtyResult<()> {
    unsafe {
        TerminateProcess(self.process_handle, 1)?;
        ClosePseudoConsole(self.hpc);      // ← FIRST CLOSE
        let _ = CloseHandle(self.process_handle);
    }
    Ok(())
}

// Drop impl (lines 336-346)
impl Drop for ConPtyBackend {
    fn drop(&mut self) {
        unsafe {
            ClosePseudoConsole(self.hpc);  // ← SECOND CLOSE (double-close)
            let _ = CloseHandle(self.process_handle);
        }
    }
}
```

**Test Failure:** `session::tests::test_session_resize` (test 29/96) triggers this when:
- Session is killed via `manager.kill_session()`  (manager.rs line 227)
- Which calls `session.terminate_pty()` (session.rs line 171)
- PTY gets consumed, `terminate()` runs, then `Drop` runs → double-close

**Systemic Root:** No ownership tracking for consumed PTY state. Rust's type system COULD prevent this with `Option<HPCON>` pattern.

#### Issue #2: Memory Leak (52.1% working set growth)

**Location:** `crates/master/src/session/manager.rs`

**Mechanism:**
1. **Orphaned tokio tasks** not tied to session lifecycle
2. Two spawned tasks per session (manager.rs lines 100, 103):
   - `pty_output_loop` (line 100)
   - `monomind_detection` (line 103)
3. When session killed (line 227-247), session Arc removed from HashMap (line 230)
4. BUT spawned tasks hold their own Arc clones → session never drops
5. Tasks keep running, holding HANDLE resources (AsyncPipeReader/Writer, lines 67-79)

**Code Evidence:**
```rust
// SessionManager::create_session (lines 99-127)
tokio::spawn(Self::pty_output_loop(session.clone()));  // ← Detached task #1

tokio::spawn({                                          // ← Detached task #2
    let session_arc = session.clone();
    async move {
        let detection = detect_monomind(&working_dir);
        // ...
    }
});

// SessionManager::kill_session (lines 227-247)
let session_arc = sessions.remove(&session_id).ok_or(...)?;  // ← Removed from HashMap
session.terminate_pty().await?;                              // ← PTY terminated
// BUT: spawned tasks still hold Arc<RwLock<Session>> → never drops
```

**Observation:** `pty_output_loop` (lines 252-339) checks `session.state == Terminated` (line 262), but monomind detection task has NO cancellation mechanism.

**Systemic Root:** Task lifecycle not bound to session lifecycle. No structured concurrency pattern (e.g., `AbortOnDrop`, `CancellationToken`, or scoped tasks).

---

### Systemic Gap: Lifecycle Ownership Model

**Problem:** The architecture ASSUMES but does NOT ENFORCE:
1. PTY backend ownership is exclusive (one owner calls `terminate()`, others rely on `Drop`)
2. Spawned tasks are cancelled when session ends
3. HANDLE resources are cleaned up exactly once

**Current SRS Coverage:**
- SRS §2.1.3 defines state machine (CREATE→RUNNING→TERMINATED) ✅
- SRS §2.1.2.3 documents ConPTY API usage ✅
- BUT: No specification for resource cleanup order or task cancellation ❌

**Missing ADR:** "Lifecycle Ownership Model for Session → PTY → Tasks → Handles"

   - 10s timeout before SIGKILL
   - Matches industry standard (tmux, systemd)

### What to FIX (Targeted Implementation Changes)

#### Fix #1: ConPTY Double-Close Prevention

**Strategy:** Use `Option<HPCON>` to track consumed state

```rust
pub struct ConPtyBackend {
    hpc: Option<HPCON>,  // ← Was: HPCON (always valid)
    process_handle: Option<HANDLE>,
    // ... rest unchanged
}

async fn terminate(mut self) -> PtyResult<()> {
    if let Some(hpc) = self.hpc.take() {  // ← Consume, prevent Drop
        unsafe {
            if let Some(h) = self.process_handle.take() {
                TerminateProcess(h, 1)?;
                CloseHandle(h);
            }
            ClosePseudoConsole(hpc);
        }
    }
    Ok(())
}

impl Drop for ConPtyBackend {
    fn drop(&mut self) {
        if let Some(hpc) = self.hpc.take() {  // ← Only if not consumed
            unsafe { ClosePseudoConsole(hpc); }
        }
        if let Some(h) = self.process_handle.take() {
            unsafe { let _ = CloseHandle(h); }
        }
    }
}
```

**Impact:** Zero architectural change. Pure implementation fix. Rust's ownership prevents double-close at compile time.

#### Fix #2: Task Lifecycle Binding

**Strategy:** Use `JoinHandle` + explicit abort, or `tokio_util::task::AbortOnDrop`

```rust
pub struct Session {
    // ... existing fields
    
    /// Background tasks (aborted on session drop)
    _output_task: AbortOnDrop<JoinHandle<()>>,
    _monomind_task: AbortOnDrop<JoinHandle<()>>,
}

impl SessionManager {
    async fn create_session(...) -> Result<SessionId> {
        // ... PTY creation

        let output_task = tokio::spawn(Self::pty_output_loop(session.clone()));
        let monomind_task = tokio::spawn(monomind_detection_task(session.clone()));

        let session = Session::new(
            id, pty, shell, working_dir, rows, cols,
            AbortOnDrop::new(output_task),
            AbortOnDrop::new(monomind_task),
        );
        
        // When Session drops → tasks aborted → HANDLEs released
    }
}
```

**Impact:** Zero architectural change. Structured concurrency pattern (borrowed from Swift, Trio). Tasks cancelled when session Arc refcount → 0.

## Appendix: Why Rust's Type System SHOULD Have Prevented This

**Observation:** These bugs bypass Rust's safety guarantees because:

1. **Unsafe FFI boundary:** `ClosePseudoConsole` is unsafe, no compile-time double-close prevention
2. **Arc cycles:** Spawned tasks holding Arc<Session> create reference cycles Rust can't detect
3. **Manual resource management:** HANDLE is not `Send` by default, we unsafely impl Send/Sync (conpty.rs lines 56-60, 75-79)

**Lesson:** Even in Rust, **lifecycle discipline matters**. Unsafe code shifts correctness burden from compiler to humans. Our bugs live in that unsafe layer.

**Mitigation:** Wrap unsafe APIs in safe abstractions with compile-time lifecycle guarantees (`Option<T>`, `AbortOnDrop`, `#[must_use]`).
