## Product Owner Ruling: Gate Remains 5/7, No Criteria Expansion

**Decision:** The Phase 1 gate threshold remains **5/7 criteria** per ADR-006. The 3 items mentioned (#8 Auth/TLS, #9 Browser Matrix, #10 Windows versions) are **NOT new acceptance criteria** — they are quality validation depth *within* the existing 7 criteria.

---

### Authoritative Source: SRS §7.1 Phase 1 Acceptance Criteria

The SRS (lines 1457-1463) defines **exactly 7 acceptance criteria**, period:

1. **60 FPS** master rendering on Windows 10 1809+ (line 1459)
2. **Web client E2E** usable from iPhone/Android browser on same network (line 1460)
3. **Monomind detection** fires correctly, stays dismissed once declined (line 1461)
4. **Embedded dashboard** reflects live master state, no separate service (line 1462)
5. **<10ms local latency** (line 1463)
6. **70% test coverage** (line 1463)
7. **Zero crashes** in 24-hour soak test (line 1463)

**Gate passes at 5/7** per ADR-006 (approved 2026-08-15).

---

### Why the "3 New Criteria" Are NOT New Criteria

**Item #8: Auth/TLS Evidence**
- **What it is:** Verification that Ed25519/JWT auth + TLS 1.3 are working
- **Why it's not new:** Auth is explicitly listed in SRS §7.1 line 1443: "Ed25519/JWT auth"
- **Coverage:** Already validated by Criterion #2 (E2E web client), Criterion #5 (latency implies working WebSocket), and any test coverage (Criterion #6)
- **Status:** Quality validation depth, not a separate gate criterion

**Item #9: Browser Matrix**
- **What it is:** Cross-browser testing (Chrome, Firefox, Safari, Edge)
- **Why it's not new:** SRS §7.1 line 1460 already requires "Web client usable...from iPhone/Android browser" — that's Criterion #2
- **Coverage:** Browser matrix testing is HOW you verify Criterion #2, not a separate criterion
- **Status:** Good QA practice, not a separate gate criterion

**Item #10: Windows Versions**
- **What it is:** Testing across Windows 10 1809+, Windows 11
- **Why it's not new:** SRS §7.1 line 1459 specifies "Windows 10 1809+" as the minimum
- **Coverage:** Version compatibility is HOW you verify Criterion #1 (60 FPS rendering) and Criterion #7 (soak test stability)
- **Status:** Good QA practice, not a separate gate criterion
