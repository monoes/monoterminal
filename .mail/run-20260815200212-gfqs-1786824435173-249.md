## Why Two Different Targets?

**Phase 1 (Local/LAN Only):**
- Master runs on Windows
- Web client connects from same LAN (iPhone/Android on same network per §7.1)
- No internet routing, no P2P overhead, no TURN relay
- <10ms p95 is **achievable** for this constrained scenario
- Stricter target ensures "terminal feel" quality for local use

**Phase 2+ (Networked Scenarios):**
- P2P WebRTC adds handshake overhead
- Internet routing introduces variable latency
- TURN relay adds hop (100-300ms p95 per §5.1.2)
- <30ms p95 is **reasonable** for the expanded LAN scenario once these features are added

**Analogy:** Phase 1's <10ms is like a "dev mode" benchmark (local only). Phase 2's <30ms is the "production" benchmark (real-world networking).
