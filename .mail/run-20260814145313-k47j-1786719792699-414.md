**Status:** Design Complete, Ready for Review

I've completed the comprehensive architecture design for the Monomind Bridge integration. This is a first-class Phase 1 feature designed explicitly to avoid the failure modes we experienced during our own build (monoes/monomind#135, #136).

## Deliverables

**1. Design Document:** `docs/monomind-bridge-design.md` (14 sections, 60+ pages)

**2. Core Architecture:**
- **Per-Session Detection (§2.4.1)**: Walk upward from PTY cwd, dismissible per-project banner with one-line install command
- **Embedded Dashboard (§2.4.2)**: HTTP API in master daemon, JWT-authenticated, serves org/agent/run/memory stats to web client
- **Health Check & Upgrade (§2.4.3)**: Daily + on-demand checks, visible status chip, one-click upgrade with confirmation
- **Hook Integration (§2.1.5)**: SESSION_START, PRE_COMMAND (<100ms), OUTPUT_STREAM (<5ms), POST_COMMAND, SESSION_END with secret redaction
- **crates/monomind-bridge**: Clean interface, no circular deps, optional via feature flag

**3. Key Design Decisions:**

| Decision | Rationale |
|----------|-----------|
| **Embedded, not separate service** | Prevents monoes/monomind#135 (dropped auth) and #136 (dead pairing) by using session JWT |
| **Fail loud, not silent** | Every integration failure surfaces visibly in UI (status chip, error modals) |
| **Performance budgets enforced** | PRE_COMMAND <100ms with timeout, OUTPUT_STREAM <5ms via chunk skipping |
| **Secret redaction built-in** | All hook inputs redact API_KEY/PASSWORD/TOKEN patterns |
| **Optional feature flag** | Build succeeds with `--no-default-features` |

**4. API Specification:**

```
GET  /api/monomind/status/:session_id  → OrgStatus (JWT auth)
GET  /api/monomind/health/:session_id   → HealthStatus
POST /api/monomind/upgrade/:session_id  → UpgradeResult (gated)
POST /api/monomind/dismiss/:session_id  → 200 OK
```

**5. Crate Structure:**

```
crates/monomind-bridge/
├── src/
│   ├── lib.rs         # Public API
│   ├── detection.rs   # Directory walking, dismiss logic
│   ├── health.rs      # Doctor checks, upgrade, scheduler
│   ├── hooks.rs       # Lifecycle hooks with budgets
│   └── dashboard.rs   # Org/agent/run status queries
└── Cargo.toml
```

**6. Integration Points:**

- **Session Manager**: Triggers detection on session creation and cwd change
- **HTTP Server**: Exposes dashboard API endpoints
- **Web Client**: `MonomindDashboard` component + `InstallSuggestion` toast
