## 4. TLS Certificate Strategy ✅

### Phase 1: Self-Signed Certificates (TOFU Model)

**Implementation:** `docs/certificate-management.md` (520 lines, complete)

**Certificate Generation:**
- Auto-generated on first startup via `rcgen` crate
- Storage: `~/.monoterminal/cert.pem` + `key.pem`
- Algorithm: RSA 2048-bit
- Validity: 365 days
- Subject: CN=monoterminal-master

**Client Trust Model:**
- TOFU (Trust On First Use) with SHA-256 fingerprint pinning
- First connection: User confirms certificate, client stores fingerprint
- Subsequent connections: Fingerprint match required
- Certificate change: User warned, must explicitly re-approve

**Certificate Rotation:**
- Auto-regeneration when expiry < 30 days
- Client impact: "Certificate changed" warning, re-approval required

**Security Note:** TOFU vulnerable to MITM on first connection (acceptable for Phase 1 dev/testing).

### Phase 2+: Let's Encrypt (ACME)

**Prerequisites:**
- Public domain (e.g., terminal.example.com)
- Port 80 open (HTTP-01 challenge) OR DNS API (DNS-01)
- Static IP or dynamic DNS

**Implementation Plan:**
- Crate: `instant-acme` or `acme-client`
- Automated acquisition + renewal (90-day certs, renew at 30 days)
- Graceful reload: Zero-downtime cert updates via `tokio::sync::watch`
- Monitoring: Prometheus metrics for cert expiry, renewal success/failure

**Status:** Documented, not implemented (Phase 2 requirement)
