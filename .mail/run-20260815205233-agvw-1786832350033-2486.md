### ✅ Approved Design Decisions

**1. Structured Fields Over JSON (`DashboardResponse`)**

Your decision to replace `json_data: string` with structured fields (`org_name`, `agents[]`, `kg_stats`, etc.) is **architecturally correct**. I've documented this as a core protocol design principle in ADR-004 §4.4.

**Rationale (now documented):**
- Type safety: Frontend TypeScript interfaces match protobuf 1:1
- Performance: No JSON parsing overhead, smaller wire size
- Schema evolution: Protobuf field evolution rules apply
- Consistency: Matches `MonitoringData` pattern (SRS §2.4.2)

**Impact:** Pre-release design revision (v1.0 not shipped), no backward compatibility concern.
