### Technical Specifications (Per Approved Phase 3 Architecture)

**1. Socket activation?**
✅ **NO** - Deferred to Phase 3.5 (per ADR-016)
- Rationale: Feature parity doesn't require it (Windows doesn't have it)
- Always-running daemon on all platforms

**2. User service or system service?**
✅ **System service** (both platforms)
- Linux: systemd system service (not user service)
- macOS: Launch daemon (not launch agent)
- Runs at system level, auto-starts on boot

**3. CLI support --system and --user?**
✅ **System only** (no --user flag needed)
- Single mode: `monoterminal-master install-service`
- Always installs system service
- Future: Add --user in Phase 3.5 if needed

**4. Privilege level?**
✅ **Root required** (sudo)
- Installation requires root/administrator privileges
- Service files in system directories (/etc/systemd, /Library/LaunchDaemons)
- CLI checks for root, prompts for sudo if needed

**5. Auto-start on boot?**
✅ **YES** (both platforms)
- systemd: `WantedBy=multi-user.target`
- launchd: `RunAtLoad=true` + `KeepAlive=true`

### systemd Design (Linux)

**Unit file design:**
- Type: `Type=notify` (readiness signaling)
- Restart: `Restart=on-failure`
- Target: `WantedBy=multi-user.target` (boot auto-start)
- User: `User=monoterminal` (dedicated service user)
- Working directory: `/var/lib/monoterminal` (from task-53)
- Logs: `StandardOutput=journal` + custom `/var/log/monoterminal`

**No socket activation** (deferred to Phase 3.5)

---

### launchd Design (macOS)

**Plist design:**
- Type: Launch daemon (system-level)
- Location: `/Library/LaunchDaemons/com.monoterminal.master.plist`
- RunAtLoad: `true` (boot auto-start)
- KeepAlive: `true` (restart on crash)
- User: `_monoterminal` (dedicated service user)
- Working directory: `/Library/Application Support/MONOTERMINAL` (from task-53)
- Logs: `StandardOutPath` + `StandardErrorPath`
